## Agent 怎么落地

### 斯坦福新课教你怎么让 Agent 真正 7×24 自动跑起来

<Tweet id="2108921711324520500" />

**这是在说什么**

跳表（Skip List）是种链表升级版，像地铁快线+站站停组合，这里指 Agent 任务调度时跳过空闲状态直接唤醒；上下文指针化压缩，就是不传整段对话历史，只传关键句的内存地址——类似微信聊天里只发「见第3条」而不是把前 200 条重发一遍。这课讲的是怎么让 Agent 不卡死、不爆内存、不互相抢活干。

**我们能学到什么**

- 别先堆 LLM，先搭好事件驱动+无状态休眠的底座
- 多 Agent 解耦不是分角色，而是按‘谁该对哪个错误负责’来切
- Harness 不是监控面板，是让失败任务能被其他 Agent 接手重试的胶水

### Agent 不需要 PR 流程，人类那套 Git infra 正在被重写

<Tweet id="2110165989027426810" />

**这是在说什么**

CDN 是内容分发网络，像全国快递前置仓；Cache-Control 是 HTTP 头，告诉浏览器‘这张图 1 小时内别再问服务器要’；这里类比的是：Agent 天然自带缓存、预热、就近执行能力，PR 这种‘先打包、再提交、等人批’的流程，对它就像给高铁修绿皮车站。Anthropic 重写 Git，本质是让每次 diff 都自带可执行上下文和回滚快照。

**我们能学到什么**

- 新项目 Git workflow 直接从 trunk-based development + auto-merge 开始
- PR 描述模板里删掉‘请 reviewer 注意’，换成‘本次变更触发的 3 个自动验证结果’
- 把 CI/CD pipeline 拆成 agent-native 的 event-driven chain，而不是 shell 脚本串行

## Code Review 别背八股

### 大厂真人代码评审其实多数走形式，连边界检查都难全覆盖

<Tweet id="2109558827788243276" />

**这是在说什么**

按常理理解是：人脑短期记忆有限，看别人写了几天的代码，就像让你快速听懂一段没字幕的方言播客。命名、空指针这些规则类问题还能扫一眼，但模块耦合度高不高、状态机有没有漏分支，靠人工 CR 基本靠运气。更别说没人考核你 CR 质量，KPI 只盯你合没合并。

**我们能学到什么**

- 把 CR 时间省下来，加到单元测试覆盖率和 contract test 上
- CR checklist 必须带自动化检查项（比如 ‘是否调用了已标记 deprecated 的函数’）
- 发现有人自己给自己 CR，就该立刻关掉那个平台的自评开关

### 不 review 代码，反而可能提升质量？这是个正经工程问题

<Tweet id="2109614783918190978" />

**这是在说什么**

这条不是鼓吹放任不管，而是说：与其把质量押在‘人眼能不能看出 bug’上，不如押在‘代码能不能自己证明它没错’上。比如用 property-based testing 生成千组边界输入，或用 formal spec 工具验证状态迁移合法性。这比让三个人各看一遍同一段代码更可靠。

**我们能学到什么**

- 把‘必须有 CR’改成‘必须有可复现的验证证据’
- 优先建轻量级 pre-commit hook，自动拒收没覆盖新增路径的 PR
- 质量目标不是‘零 bug’，而是‘bug 出现后 2 分钟内自动 rollback’

## 岗位现实

### 人类 Reviewer 也管中窥豹，AI 幻觉不该是‘有人审就安全’

<Tweet id="2109472993629941804" />

**这是在说什么**

B+ 树是数据库索引常用结构，像图书馆目录柜——只存关键页码，不存全文；这里类比的是：每个开发者只掌握自己模块的‘目录’，没人真记得所有接口的副作用。所以指望人类 Reviewer 全局把关，就像指望图书管理员光看目录就发现某本书被偷偷篡改了内容。

**我们能学到什么**

- 强制要求每个 PR 关联变更影响图（哪怕只是 auto-gen 的 call graph）
- 新人 onboarding 时第一周不写代码，只画他要改模块的依赖快照
- 把‘全局视角’从人脑转移到可观测性工具链里
